# Решение владельца по Shelter (задача 1 круга 4)

Дата: 24.08.2026. Решение принято владельцем проекта.

## Выбран вариант А: перемещение ручных броней убрать

`computePullDownRepack` (`src/app/api/mirror/_lib/repackBookings.ts`) больше не должен
переставлять брони менеджеров между номерами. Shelter становится обычным зеркалом: пишет
только свои метки `mirror_shelter`, чужие строки не трогает.

**Почему так.** Правило проекта — «ручные брони не двигать» — держалось всю работу, и
Shelter был единственным исключением. Совпадение порядка номеров с системой отельера не
стоит риска: перемещение молча глотало конфликты, а менеджер не понимал, почему его бронь
оказалась в другом номере.

## Что сделать

1. **Убрать перемещение из `syncShelter`** (`syncMirror.ts`): не вызывать
   `computePullDownRepack`, не выполнять `UPDATE reserves SET room_id`. Поле `movedBookings`
   в результате синка оставить для совместимости, но оно всегда 0 — либо убрать вместе со
   всеми потребителями, если это не ломает вызывающий код.
   Сам модуль `repackBookings.ts` и его тесты можно удалить, если после этого он больше
   нигде не используется (проверить `grep`).

2. **Перевести запись на транзакционную процедуру** `sync_external_occupancy` — по образцу
   уже переведённого `syncKontur` в том же файле (коммит `6f5f698`). То же самое для ветки
   Shelter в `scripts/mirror-cron-sync.mjs`.

3. **Научить читалку сообщать о полноте ответа.** `shelterFrontdesk.ts` сейчас при сбое сети
   молча отдаёт пустую занятость — отель будет выглядеть полностью свободным. Нужен признак
   `sourceComplete`, как это сделано в `reservationstepsIcal.ts` и `konturBookonline.ts`
   (считать неудачные запросы и возвращать флаг). Передавать его в `p_source_complete`.

4. Пороги защиты брать те же, что у остальных зеркал:
   `getTransactionalIcalMinRetainedRatio()` и `isLargeIcalDecreaseConfirmed()`.

## Что проверить и показать в PR

Отели: **Сан Амра, Нора, Студио Сан Амра**.

- занятость по ночам до и после перевода совпадает (diff = 0);
- ручные брони менеджеров **остались в своих номерах** — ни одна не сдвинулась;
- пустой ответ источника не стирает занятость (сымитировать), в `sync_runs` попадает ошибка;
- `manual_belvedere` не затронут;
- `npx tsc --noEmit`, `npm run test`, `npm run build`, ESLint — зелёные.

Проверять на боевых данных внутри `BEGIN; … ROLLBACK;` — приём описан в
[hardening-round4-codex.md](./hardening-round4-codex.md).

## Отдельно: последствия для вида шахматки

После отключения перемещения занятость Shelter-отелей может выглядеть «рваной»: метки
робота встанут на свободные строки, а ручные брони останутся там, где их поставил менеджер.
Число свободных номеров при этом остаётся верным — меняется только расположение по строкам.
Это ожидаемо и согласовано.
